# Проверка PR и ответ на замечания

Цель — чтобы находки дошли до исполнителя без автора-посредника и каждая закрылась доказательством.

## Проверяющий

1. **Начни с описания PR и diff**, а не с репозитория. Открывай другие файлы, только если на них ссылается diff. Широкий поиск отдавай субагенту и бери от него только вывод.
2. **Проверь передачу.** В описании шесть разделов (Что и зачем · Как проверено · Не проверено · Риски · Решения без автора · Урок для журнала); их проверяет `scripts/check_pr_handoff.py` в CI.
3. **Доверяй, но проверяй.** Перезапусти хотя бы одну команду из «Как проверено» (лучше ту, что ближе к риску). Расхождение с заявленным результатом — замечание P1.
4. **Пройди «Code Review Rules» из AGENTS.md** и gates §9 для затронутых областей.
5. **Оформи находки** таблицей: приоритет P0–P3 · `файл:строка` · что не так · доказательство (команда, тест, скриншот). Без доказательства пометь находку как гипотезу.
6. **Вердикт одной строкой:** «можно сливать», «сливать после исправлений P0–P1» или «не сливать» — и почему.
7. **Публикация.** Если есть доступ к GitHub — оставь всё это одним комментарием в PR. Последняя строка комментария, отдельно:
   `@codex исправь находки P0–P2 из этого комментария в этой же ветке и ответь на каждую по AGENTS.md §8`
   Нет доступа — отдай автору текст комментария целиком; ему останется вставить его в PR.
8. **Урок.** Находку, которую пропустили тесты, предложи строкой для `docs/agents/lessons.md`: дата · категория · что случилось · чем закрепить.

## Исполнитель, отвечающий на замечания

- По каждой находке — «исправлено (коммит)», «отклонено (доказательство)» или BLOCKED. Без согласия без проверки и без спора без доказательства.
- Исправления — новыми коммитами в ту же ветку; одна ветка — один пишущий агент.
- Если находку пропустили тесты, добавь строку в журнал уроков и заполни раздел «Урок для журнала» в описании PR. Вторая находка той же категории закрепляется тестом, аудитом или хуком — этого требует `tests/test_agent_setup.py`.
