# English Encyclopedia — проверяемое развёртывание Django на Render

## Что делает Blueprint

`render.yaml` создаёт **один веб-сервис** Render. Он не покупает сервер,
не создаёт/удаляет базу и не обращается к реальным ученикам.
Команды `deploy/render-build.sh` ставят фиксированные зависимости,
Gunicorn и собирают WhiteNoise-статику. `deploy/render-start.sh` запускает
миграции, первоначальную загрузку контента и Gunicorn на Render `$PORT`.
Путь `/healthz/` проверяет соединение с БД через SELECT 1; ошибка БД
возвращает HTTP 503.

## Настройка без ручного изменения исходников

1. Выберите постоянный PostgreSQL (например, уже существующий Supabase).
   Критично: бесплатный Render PostgreSQL **истекает через 30 дней**,
   без поддерживаемых резервных копий — не используйте его для учёбы людей.
2. На https://dashboard.render.com откройте Blueprints → New Blueprint
   Instance, подключите GitHub `konstantin532/English-Encyclopedia`.
   Для проверки укажите ветку PR; после ручного merge — `main`.
3. В Render **только в приватных Environment Variables** заполните
   `DATABASE_URL` целым адресом подключения PostgreSQL, с TLS. Никогда
   не вставляйте URL, пароль или secret в GitHub, issue либо логи.
   `DJANGO_SECRET_KEY` создаётся автоматически.
4. `RENDER_EXTERNAL_HOSTNAME` Django берёт у Render автоматически.
   Если нужен собственный домен, добавьте его в `DJANGO_ALLOWED_HOSTS`,
   а `https://домен` в `DJANGO_CSRF_TRUSTED_ORIGINS`.
5. Проверьте в браузере `https://<имя>.onrender.com/healthz/`, затем
   A1, регистрацию, личный кабинет, словарь, четыре независимых ответа
   и адаптацию 320–430 px. Заполните чек-лист Android/TalkBack.
6. Прежде чем приглашать учеников, настройте у провайдера PostgreSQL
   автоматические **резервные копии** и реально проверьте восстановление
   в отдельной БД. Не используйте продакшен-учеников в тестах.

## Реальная озвучка и статика

Синтезированные записи **не входят в GitHub** и не появятся на сайте
после одного лишь развёртывания. Запустите вручную GitHub Action
`Build real A1 speech for manual review`, получите пакет 33 комплектов,
проверьте транскрипт, американское произношение и ударения человеком.
Чтобы включить файлы на Render, после создания **настоящего** комплекта
скачайте артефакт GitHub Actions с `static/audio/` и `audio-human-review.csv`.
Исходный `a1-generated-audio.zip` в этом артефакте **ещё не проверен
человеком**. Прослушайте все 99 дорожек (33 комплекта × три скорости), впишите
в таблицу настоящие результаты: фамилию/имя рецензента (`reviewer`), дату
`YYYY-MM-DD` (`review_date`), `pass` во всех четырёх полях фонетики,
ударения, интонации и имён/чисел, и `manual_approved=yes` только после
реального прослушивания. Если запись звучит неестественно, **не ставьте
`pass`**: исправьте генерацию и прослушайте новый файл.

Из корня проекта с восстановленными `static/audio` и заполненной CSV:
```bash
uv run python -m scripts.approve_audio_review --sheet audio-human-review.csv --dry-run
uv run python -m scripts.approve_audio_review --sheet audio-human-review.csv
uv run python scripts/audio_readiness.py --strict --require-reviewed
uv run python -m scripts.package_audio_archive --require-reviewed --output a1-reviewed-audio.zip
sha256sum a1-reviewed-audio.zip
```
Команда проверит **99 совпадений SHA-256** с таблицей, отсутствие пропусков,
полноту и одобрение всех критериев, а затем пометит манифесты как
`verified: true` вместе с именем проверившего и привязкой к точным
аудиофайлам. Изменение хотя бы одной дорожки после проверки снимает её
статус в аудите: нужен повторный ручной разбор. Это запись о проверке,
**не автоматическая оценка речи и не криптографическая подпись рецензента**.

Затем разместите `a1-reviewed-audio.zip` по стабильной HTTPS-ссылке,
доступной Render при сборке
(например, в предназначенном для этого объектном хранилище).
Введите в Render приватные переменные
`A1_AUDIO_ARCHIVE_URL` и `A1_AUDIO_ARCHIVE_SHA256` (контрольная сумма
zip из журнала сборки). Сборочный скрипт скачает архив, сравнит SHA256,
отклонит опасные пути и повреждённые комплекты и **до collectstatic**
поместит записи в `static/audio`. При запуске `load_content` свяжет
манифесты с уроками. Менять только одну из этих двух переменных нельзя:
сборка остановится. Для полного качества по-прежнему необходимо
слуховое одобрение экспертом: синтезатор не ставит флаг `verified`
автоматически. Render Free не сохраняет файлы, созданные после сборки,
поэтому нужен устойчивый источник архива. Если URL не задан, сайт
нормально собирается **без аудио** и не делает вид, что оно есть.

## Эксплуатационные ограничения

- Free веб-сервис останавливается после 15 минут без запросов и может
  запускаться около минуты. Это не постоянный SLA для реальных учащихся.
- База данных обязательна: конфигурация production намеренно откажется
  работать на локальном SQLite; ошибки миграций блокируют запуск.
- Не выключайте `SECURE_SSL_REDIRECT` или CSRF ради «лечения» ошибки.
- Проверьте `uv run python manage.py check --deploy` с настоящими
  переменными окружения; не записывайте секреты в лог.
- Для отката используйте Render Dashboard, версионирование GitHub и
  **совместимые** миграции. При изменении схемы БД прежде проверьте бэкап.
- Render «Deploy succeeded» и HTTP 200 не подтверждают CEFR и освоение речи.

## Диагностика

- **400 Bad Request** — проверьте имя в `DJANGO_ALLOWED_HOSTS`.
- **CSRF 403** — HTTPS-адрес в `DJANGO_CSRF_TRUSTED_ORIGINS`.
- **503 /healthz** — проверьте доступность PostgreSQL, SSL и миграции.
- **Не видно оформления** — проверьте вывод `collectstatic`, WhiteNoise,
  браузерный Network (статус 404) и `STATIC_URL`.
- **Нет голоса** — сначала проверьте наличие реальных ассетов и загрузку
  `manifest.json`; браузерный Web Speech en-US зависит от устройства.
