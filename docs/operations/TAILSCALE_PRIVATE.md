# English Encyclopedia — приватный доступ через Tailscale (Windows + Android)

**Цель:** открывать сайт на своих телефонах/компьютерах из любой сети. При этом веб-приложение остаётся на домашнем Windows-ПК, а доступен он **только** устройствам, которым разрешён вход в ваш Tailscale tailnet.

**Граница изменений:** эта инструкция и пусковой скрипт находятся в отдельной ветке `feature/tailscale-private-preview`, основанной на `feature/a1-active-studio-lessons-01-18` (PR №15). Ветки `main` и `situation-weeks` не менялись. Для доступа к 108 новым ситуациям запускать именно эту ветку. Никакого автоматического слияния.

## Что необходимо

- Домашний компьютер с Windows 10/11, интернетом и рабочей копией проекта (необходим установленный `uv`).
- Tailscale на домашнем компьютере и на каждом устройстве, с которого будете открывать сайт. Вход под одной учётной записью или в одну разрешённую сеть (tailnet).
- Компьютер должен оставаться включённым, Tailscale — подключённым, а окно с сервером — открытым. Для работы после перезагрузки сайт нужно снова запустить.
- **Не** открывать порт 8000 на роутере, **не** использовать `tailscale funnel`, **не** публиковать секретный ключ и базу в GitHub.

Установка Windows: https://tailscale.com/docs/install/windows
Установка Android: https://tailscale.com/docs/install/android
Tailscale Serve: https://tailscale.com/docs/features/tailscale-serve

## Первый запуск

1. Установите Tailscale на Windows, войдите в приложение, убедитесь, что состояние «Connected».
2. Установите Tailscale на Android, войдите в ту же сеть, включите соединение/VPN.
3. На домашнем компьютере возьмите нужную ветку проекта:

   ```powershell
   git fetch origin
   git switch --track origin/feature/tailscale-private-preview
   ```

   Если эта ветка уже создана локально, выполните `git switch feature/tailscale-private-preview`. **Не используйте** обычный `start.bat` для удалённого доступа: он запускает небезопасный для удалённой публикации Django dev-server с DEBUG=True.

4. Запустите двойным щелчком **`start_tailscale_private.bat`** из корня проекта. Скрипт:
   - определяет точное Tailscale DNS-имя ПК;
   - задаёт `config.settings.production`, `DEBUG=False`, точные `ALLOWED_HOSTS` и `CSRF_TRUSTED_ORIGINS`;
   - при необходимости генерирует постоянный случайный `DJANGO_SECRET_KEY` в локальном `.env`, не записывая секрет в GitHub;
   - устанавливает зависимости и запускает миграции, загружает курс и готовит статические файлы;
   - запускает **Waitress** только на `127.0.0.1:8000`, а не на общедоступном интерфейсе;
   - выводит личный адрес вида `https://имя-пк.имя-tailnet.ts.net/`.

5. **Один раз** включите Tailscale Serve. Откройте отдельное **Windows Terminal (Администратор)** и выполните:

   ```powershell
   tailscale serve --bg 8000
   tailscale serve status
   ```

   При первом запуске Tailscale может попросить разрешение на HTTPS-сертификаты через страницу настройки — выполните этот шаг в Tailscale. Команда включает **Serve**, не публичный **Funnel**. Если PowerShell не находит `tailscale`, используйте `& "C:\Program Files\Tailscale\tailscale.exe" serve --bg 8000`.

6. На Android откройте личный адрес из окна сервера в Chrome или другом браузере. Для диагностики сначала выключите Wi-Fi на телефоне и проверьте через мобильную сеть — это подтвердит, что работает именно удалённый доступ. Проверьте `/levels/a1/` и `/lab/a1/18/`.

## Повторный запуск

- Tailscale на обоих устройствах должен быть включён.
- Дважды нажмите `start_tailscale_private.bat` на Windows; Serve, настроенный с `--bg`, сохраняет конфигурацию после перезапуска Tailscale. Сам Django/Waitress сервер **не** остаётся работать после закрытия консоли.
- Если ПК уходит в сон, сайт недоступен. Для частой работы отрегулируйте питание ПК и позаботьтесь о резервной копии данных.

## Как отключить доступ

В Windows Terminal (Администратор) выполните:

```powershell
tailscale serve off
```

Это снимает публикацию в tailnet. Сервер в открытом окне можно остановить `Ctrl+C`. Команду `tailscale funnel` **не использовать**, она публикует сайт всему интернету.

## Особенности проекта

- Исходный сайт — полноценный Django, не статический набор HTML. Поэтому GitHub Pages здесь недостаточен.
- Скрипт **не** хранит новые ответы мини-практик `/lab/a1/1/` … `/lab/a1/18/`. Остальной сайт может хранить аккаунты и прогресс в настроенной базе. Если в `.env` уже указан `DATABASE_URL` на Supabase, скрипт использует **эту существующую базу**; перед первым запуском проверьте, нужна ли отдельная тестовая база и резервная копия. При пустом `DATABASE_URL` используется локальная SQLite.
- Получить доступ с **любого произвольного компьютера без установки Tailscale** через приватный Serve нельзя. Для компьютера, который вам принадлежит/которым вы управляете, добавьте его в свой tailnet; не входите в свою учётную запись Tailscale на чужих общедоступных ПК.
- Tailscale даёт частную сеть, но **не заменяет** авторизацию внутри Django. Используйте нормальные пароли и не передавайте доступ посторонним.
- Готовые аудиодорожки Kokoro требуют отдельной генерации. Если они отсутствуют, часть упражнений использует системный голос `en-US` устройства.
- Сначала проверьте вход, выход, формы, CSS/JS, звуки, мобильную раскладку и качество микрофона на реальном Android. Даже успешные автоматические тесты не доказывают, что всё работает на каждом устройстве.

## Типичные проблемы

| Симптом | Проверка |
| --- | --- |
| `DisallowedHost` или ошибка 400 | Открывайте **точный** HTTPS-адрес, напечатанный скриптом. После переименования ПК перезапустите `.bat`. |
| `403 CSRF` при входе | Убедитесь, что используется HTTPS-адрес из Tailscale Serve; скрипт устанавливает для него `DJANGO_CSRF_TRUSTED_ORIGINS`. |
| Телефон не открывает сайт | Проверьте, что Tailscale подключён **на обоих** устройствах, ПК не спит, окно сервера открыто и `tailscale serve status` показывает прокси. |
| Ошибка Tailscale HTTPS | Tailscale может запросить первое подтверждение включения HTTPS в панели сети. |
| Нет оформлений или звука | Проверьте успешность `collectstatic`. Реальная Kokoro-озвучка создаётся отдельно. |
| Команда `uv` не найдена | Установите uv по https://docs.astral.sh/uv/getting-started/installation/ и снова запустите скрипт. |

## Безопасность

- В конфигурации Django используется `config.settings.production`, а `DJANGO_SECRET_KEY` не выводится пользователю и игнорируется Git через `.gitignore`.
- HTTP между Tailscale Serve и Waitress остаётся **только локальным** (`127.0.0.1`); соединение с мобильного устройства идёт по HTTPS внутри tailnet.
- Не сохраняйте действительные ключи, реальные телефонные номера и учётные данные в шаблонах уроков, снимках экрана или репозитории.
