# Лаборатория «В кафе» — этап аудирования и живой речи

Статус: **готово подключение; настоящая генерация аудиофайлов и человеческая фонетическая проверка остаются внешними действиями**. Ветка `feature/cafe-lab-kokoro-audio`. По состоянию на 16 октября 2026 года.

## Что изменено

1. Для `/lab/cafe/` создана единая серверная структура из 6 реплик `CAFE_DIALOGUE`; одна и та же структура используется генератором и страницей Django.
2. Ученик выбирает один из трёх темпов: **очень медленно / медленно / естественно**. При наличии настоящих локальных дорожек Kokoro слышны **разные синтезированные голоса Мии и Тома**; настройки взяты из `content/manifests/voices.yaml` (`af_bella` и `am_michael`).
3. Можно ставить на паузу, останавливать запись, воспроизводить отдельную реплику; подсветка реплики синхронизирована с таймингами манифеста. После смены темпа воспроизведение останавливается, чтобы не было рассинхронизации.
4. При отсутствии записанных файлов сохраняется fallback на **системный синтез en-US**, только если такой голос предоставлен браузером. Нет голоса — нет ложной кнопки записи; текст полностью доступен.
5. **Пилот остаётся отдельно от существующего диалога недели 3**, база данных, миграции, словарь и `situation-weeks` не затронуты.

## Создание настоящих файлов, когда модель Kokoro уже установлена

```bash
uv sync --group audio
uv run --group audio python scripts/generate_cafe_lab_audio.py
```

- Генератор повторно использует `scripts/generate_story_audio.py`, проверенную модель Kokoro и `voices.yaml`.
- Выход: `static/audio/cafe-lab/voice_very_slow.mp3`, `voice_slow.mp3`, `voice_natural.mp3` (или WAV в среде без MP3) плюс `manifest.json`.
- Полученные аудиофайлы должны быть развёрнуты вместе со статическими файлами или помещены в предоставляемое на сайте хранилище; **сам merge Python/JS кода не генерирует и не публикует бинарную озвучку**.
- Неверифицированный звук будет обозначен `verified=false`, даже если технически правильный.
- Файлы модели Kokoro и голосов не следует добавлять в GitHub-репозиторий.

## Защита от тестовых сигналов

Для проверки конвейера:
```bash
uv run --group audio python scripts/generate_cafe_lab_audio.py --engine test
```
Это создаёт только `static/audio/cafe-lab-test/`. Такие файлы **никогда не выберутся плеером**. Сервер игнорирует manifest без `engine=kokoro`, с незнакомой моделью/голосами, со ссылкой на файлы вне выделенного каталога, с отсутствующими/пустыми файлами, повреждёнными таймингами или неподходящим количеством реплик.

Сервер поставляет браузеру только отфильтрованные URL и тайминги. В тестах отдельно проверяются test-tone, нарушение путей, посторонние символические ссылки, несогласованность разметки реплик. Даже валидный манифест **не доказывает**, что произношение естественное: нужен лингвистический обзор.

## Что остаётся на следующем этапе

- Реально выполнить команду с доступными моделями, прослушать **каждую** реплику медленного и естественного темпа.
- Проверить темп, паузы, ударение, уместность интонации и то, что в диалоге чётко различаются `one tea and one coffee` и `two coffees`.
- Проверить работу на Android и ПК, включая запрет микрофона, нет голоса en-US, слабую сеть и отсутствие готовых файлов; только после этого подтвердить качество опыта.
- Доработать адаптивные контрольные проверки на понимание устной речи, самостоятельную продукцию и перенос на новые ситуации, а после пилота — подключать сохранение прогресса.
- Не считать синтез речи автоматической проверкой правильности произношения ученика.
