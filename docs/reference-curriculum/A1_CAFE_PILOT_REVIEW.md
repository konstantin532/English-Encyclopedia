# Контрольная точка: сравнительная проверка урока «В кафе»

Дата: 2026-10-16. Статус: **редакторский обзор по исходникам; не результат испытания на учениках**.
Ветка: `experiment/touchstone-inspired-curriculum`.
Сравниваем:
- действующий `main`: `content/seed_lessons/a1_w03_l05_cafe.yaml`, `content/seed_weeks/a1_w03.yaml`;
- эксперимент: `docs/reference-curriculum/ORIGINAL_A1_CAFE_PILOT.md`.
- техническое ограничение: `apps/drills/models.py` — `Exercise.Kind` поддерживает `choice/fill/build`, `Exercise.is_correct` сравнивает нормализованный ответ с конечным списком `answer + accepted`.

## 1. Главный ответ

**Не заменять исходный урок целиком.** В нём уже есть полезные 7 слоёв, лексика заказа, сокращения, IPA, задания и переход к новой ситуации. Новый прототип добавляет отдельный диалог **исправления неверно услышанного заказа**, где ученику приходится самостоятельно реагировать на ошибку.

Предпочтительное решение — сохранить текущую жизненную ситуацию и сюжет, исправить спорные трактовки речи и добавить *один новый переносимый навык*, а не копировать или переименовывать главы учебника.

## 2. Сверка возможностей — доказуемое и недоказанное

| Критерий | Уже есть в текущем A1 | Даёт эксперимент / что остаётся |
|---|---|---|
| 7 смысловых слоёв | Есть в YAML | Сохранить, а не множить объяснения |
| Вежливые просьбы | `Can I have…?`, `I'd like…`, `please` | Пояснить контекст, тон, не делать `Give me` абсолютным запретом |
| Разговорная практика | `Сыграть роль`, spoken/full, три темпа в архитектуре | Нужна проба **без готового сценария** |
| Понимание на слух | Запланированный аудиорежим | Новую запись ещё нужно сделать и прослушать человеком |
| Письменная проверка | `choice/fill/build`, проверка по ответам/accepted | Свободный ответ пока нельзя автоматически оценить полноценно по смыслу |
| Перенос навыка | Есть задания `stage: transfer` | Проверить перенос в ситуацию **без списка допустимых фраз как единственного критерия** |
| CEFR/AmE | Конструкции введены; много `cefr: unverified` | Требуется независимая проверка уровня, естественности и произношения |
| Авторские права | Собственный существующий материал сайта | Прототип собственного сюжета; не воспроизводит чужие учебные тексты |

### Конкретные исправления действующего урока

1. Вместо `Give me… звучит грубо` объяснить: **форма звучит довольно прямо и без смягчения может оказаться резкой в обслуживании; естественность зависит от интонации, отношений и контекста**.
2. Вместо `I want — так говорят друзьям и детям` объяснить: **I want сообщает о желании прямо; в заказе часто выбирают более мягкое I'd like / Can I have; само по себе want не является грубым или детским словом**.
3. Упражнение с единственным «вежливым» вариантом `I would like a tea, please.` не должно учить, будто `I want tea` **всегда** невежливо; точнее формулировать «Какой ответ звучит наиболее мягко **в этой ситуации**?».
4. Для `Here you are` и `You're welcome` не обещать единственных обязательных способов ответа: в живом AmE используются другие нормальные варианты, но добавлять их только по доступной лексике ученика.
5. Если ученик слышит `Two coffees?` вместо `one tea and one coffee`, он должен **заметить и исправить ошибку**. Эта проверка отличается от простого выбора красивой фразы.

## 3. Предлагаемый оригинальный микроурок (без вмешательства в YAML)

**Сцена:** Мия работает за стойкой. Том заказал один чай и один кофе. Из-за шума он получает неверное уточнение.

- Mia: `Good morning, Tom! What would you like?`
- Tom: `I'd like one tea and one coffee, please.`
- Mia: `Two coffees?`
- Tom: `No, sorry. One tea and one coffee, please.`
- Mia: `One tea and one coffee. Here you are.`
- Tom: `Thank you!`

Сначала слушать с закрытым текстом. Затем ответить по-русски: **Что Мия поняла неправильно?** Потом увидеть слова и маркеры. И наконец — самому ответить Мие с новым заказом.

**Задача 1 — различить смысл:** `one tea + one coffee` против `two coffees` (не проверять знание текста наизусть).

**Задача 2 — изменить:** попросить `two teas and one coffee` с грамматически правильной формой напитка как порции. Формы множественного числа проверить в реестре.

**Задача 3 — ответ без шаблона:** после реплики `Two coffees?` ученик своими словами исправляет ошибку. Засчитывать **семантическую цель**, а не одну фразу.

**Задача 4 — перенос:** другая ситуация, знакомые слова; сотрудник неправильно понял количество билетов. Если `ticket` ещё не изучено, такую задачу переносить на неделю, где оно уже введено (например, итоговую A1-неделю), либо выбрать другой уже известный предмет.

**Задача 5 — повтор:** повторить после паузы, изменив товары/количество; модель ответа открывается **после собственной попытки**, не до неё.

## 4. Минимальные требования для нового функционала

Сейчас `Exercise.is_correct` **не понимает произвольную английскую речь**: код нормализует строку и проверяет принадлежность списку допустимых ответов. Поэтому запрещено выдавать такую проверку за полноценное семантическое оценивание.

На первом этапе:
1. В тестируемом `choice/fill/build` использовать несколько явно проверенных грамматически корректных `accepted`.
2. Отдельно давать **открытый устный или текстовый ответ**. Показывать образцы и рубрику самопроверки только после первой попытки. Не записывать `correct=True` за голос без реальной проверки.
3. Для будущего кабинета преподавателя предусмотрена *необязательная* ручная проверка этой попытки: «понял ошибку / исправил / понятно произнёс / употребил уместное выражение».
4. Если позже добавлять AI-анализ аудио, обозначать его ограниченную надёжность и предусматривать обжалование ошибок. Не требовать отсутствия акцента.

## 5. Какие проверки нужны перед внедрением (сначала RED, затем GREEN)

| ID | Автоматизированное требование |
|---|---|
| CAFE-01 | Загрузка сцены не добавляет незарегистрированную лексику A1 нед. 3 и не допускает неизвестные маркеры |
| CAFE-02 | Все spoken-варианты, сокращения и множественные формы связаны с известными единицами |
| CAFE-03 | Ответ `One tea and one coffee, please` принимается в упражнении «исправление заказа» |
| CAFE-04 | Уместный вариант `No, one tea and one coffee, please` тоже принимается |
| CAFE-05 | `Two coffees, please` **не засчитывается** как исправление заданного заказа |
| CAFE-06 | Подсказка и образец не раскрываются до независимой попытки (по выбранной модели UI) |
| CAFE-07 | Ответ ученика А не влияет на прогресс ученика Б; повторные запросы не создают ложного успеха |
| CAFE-08 | Отсутствие аудио честно обозначается; тестовые служебные тоны не трактуются как живая речь |
| CAFE-09 | Редакторская проверка не выявляет незаконно заимствованных диалогов, упражнений или порядка глав |
| CAFE-10 | `audit_course`, `pytest`, `node --test` и соответствующие CI проверки проходят после реализации |

**Примечание:** CAFE-09 — человеческая редакторская проверка; её нельзя считать автоматически доказанной только кодом.

## 6. Методическая шкала качества — оценивать ПОСЛЕ пилота

Использовать десять критериев по 0–2 из `TOPIC_DECISION_MATRIX.md` (максимум 20). Сейчас цифровая оценка «9/10» была бы **недостоверной**: живое аудирование, проверка речи и реакция новичков не наблюдались. Поэтому статус у прототипа остаётся **draft**, а не `approved`.

Для маленькой добровольной проверки:
- Дать одинаковую целевую задачу 5–8 начинающим взрослым.
- До занятия спросить, могут ли они исправить неправильный заказ.
- После занятия повторить с другим напитком и числом; позже — в другой жизненной ситуации.
- Отмечать понимание, самостоятельность, число подсказок, понятность устного ответа; не обещать научную доказанность по такой маленькой выборке.
- Не публиковать голосовые записи без согласия.

## 7. Дальнейшие инженерные границы

**Можно продолжать независимо от основной разработки:** документы, методическая оценка, образцовые реплики, спецификация валидатора, план тестов.

**Нельзя без новой проверки параллельных изменений:** изменять `content/seed_lexicon/`, `content/seed_weeks/`, текущий `a1_w03_l05_cafe.yaml` или присваивать `LX-` идентификаторы. В `situation-weeks` параллельно добирают A1 до 500, и перезапись приведёт к конфликтам.

**Следующий технический шаг:** оформить безопасный отдельный тестовый YAML с каноническими моделями и разметкой только после проверки актуальных LX и регистратора; выполнить `load_content`/`audit_course`/`pytest` в изолированной среде и показать PR без автоматического слияния.

## Контроль оригинальности

Создано внутри собственного мира Anna/Tom/Mia на основе общеупотребительных грамматических фактов. Название темы `в кафе` само по себе не имеет уникальности. Чужие страницы, аудио, диалоги, задания, частная система глав или близкий пересказ не используются.
