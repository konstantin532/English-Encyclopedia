## Проход 1 — чистота независимого опыта, точность переводов

- Страница показа ответов больше **не отображает одновременно новую форму** с той же или похожей задачей. Начало следующего опыта требует отдельного GET.
- `There is water` рассматривается как «Есть вода», а не обязательно указательное «Там есть вода»; допустимый русскоязычный вариант сохранён.
- Отредактированы просьбы о произнесении букв в ситуативном американском английском, устранено повторение готового образца.
- Проверка: после отправки видны четыре образца, но нет новой слепой формы.

## Проход 2 — ввод, медленный интернет, безопасность

- При HTTP 400 (неполный ответ, устаревшая форма, повторная отправка) сервер возвращает ту же форму с **восстановленными введёнными ответами**, доступным предупреждением `role="alert"`, статусом 400 и без образцов.
- Текст ограничивается 400 символами и выводится через Django-экранирование; проверка с `<script>...` подтверждает, что код не исполняется.
- Источник правды для отправки — сервер; клиент не сохраняет ученические тексты в `localStorage` и не отправляет на сторонние сервисы.

## Проход 3 — отделить знание от подсказок

- Пять независимых prompts лишены явно указанной формы ответа `does`, `Do you`, `be`, `like`.
- Перед четырьмя ответами ученик указывает условия: без помощи, с конспектом или с переводчиком. Единый самоотчёт записывается на всех четырёх попытках; старым историческим попыткам не приписывается «без помощи».
- Добавлена миграция `0009_independent_assistance.py`; преподаватель видит факт заявленного использования помощи в Django Admin.
- Это **не средство обнаружения обмана** и не оценка CEFR. Важен добровольный корректный самоотчёт.

## Проход 4 — работа на узком экране и со скринридером

- После серверной ошибки фокус перемещается на сообщение, чтобы TalkBack/клавиатурные пользователи не пропустили причину.
- Для Android landscape введены отдельные `safe-area-inset-left` / `safe-area-inset-right`, контрастность `prefers-contrast: more`, поддержка 200%-масштаба, 52px зоны касаний и явное восстановление кнопки после `pageshow`.
- Добавлен JavaScript-регрессионный тест фокуса и CSS-контракт экранной доступности.

## Проход 5 — неточности адресата, владения и смысловой ситуации

- `Does Mia like tea?` теперь предлагается сказать **Тому о Мии**, не задавать этот вопрос самой Мии.
- `Does Anna work here?` задаётся **коллеге**, а не самой Анне.
- `The book is here` теперь соответствует «книга находится здесь», не ложному выводу, что она у говорящего.
- В ситуации с водой вопрос `Is there any water?` использует естественный контекст поездки; просьба использует `some water`.
- Регрессионные тесты фиксируют адресата, модельный ответ, соответствие вопроса и контекста, наличие одинаковых безопасных отступов для разных экранов.
- Повторная автоматическая сверка manifest охватывает **28 уроков, 84 поясняющих шага, 84 самостоятельных контекста**. Это структурная проверка, **не лингвистическая экспертиза всего курса**.

## Дополнительная защита из предыдущих двух проходов PR №29

Одноразовый токен четырёхответной формы, обязательный на сервере, плюс частично-уникальное ограничение БД предотвращают повторные записи, даже при гонке конкурентных POST. Проверка преподавателя привязана к версии исходной задачи; без её восстановления преподавательский вердикт запрещён.

## Что всё ещё ограничивает оценку

1. Нет подтверждённого тестирования на реальных Android устройствах, TalkBack, 200% текстах, слабой сети и реальной клавиатуре.
2. Нет независимой экспертной вычитки всех YAML-уроков, 815 вопросов, стихотворений и аудио американского английского.
3. Нет преподавательски проверенного пилота 5–8 учеников на новых ситуациях, включая задержанный тест через 7 дней.
4. По-прежнему не измеряются объективно свободное аудирование, произношение и реальная разговорная речь.

Не сливать PR в `main` автоматически; владелец примет решение после CI и проверки доступности.
