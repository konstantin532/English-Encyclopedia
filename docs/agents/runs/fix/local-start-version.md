# Исправление локального запуска после слияния PR

Дата: 2026-10-31. Ветка: fix/local-start-version. Baseline: origin/main 70ba319a7152f88c663491f1eb1510d6110ff375.

## Задача и воспроизведение

Автор показал старые формы входа/регистрации после слияния PR #160. Фактический сервер 127.0.0.1:8000 работал из основной папки F:/english-Encyclopedia, на ветке agents/install-learning-skills (c15fcc29); Codex принимал интерфейс в отдельной рабочей копии. На signup реального 8000 были учебное меню, поиск и поле имени, отсутствовал выбор роли. Старый start.bat делал git pull текущего upstream и продолжал запуск при ошибке, в том числе когда слитая ветка уже удалена.

## Сделано

- После проверки чистого tracked-состояния создал эту ветку от уже слитого origin/main; main не изменял и не сливал.
- Остановил только подтверждённое дерево прежнего сервера, сохранил SQLite через backup API вне Git, применил только accounts.0005. Все прежние значения в 19 таблицах аккаунтов/обучения/преподавания/сессий совпали, quick_check=ok. Контент не перезагружал.
- start.bat явно получает origin/main; обновляет только чистый checkout, являющийся его предком. Правки и неслитые коммиты сохраняются; fetch failure завершает запуск.
- Повторный запуск останавливает только собственное дерево сервера с совпадающими root/port/PID/starttime и listener ancestry. Native Windows handle удерживается до завершения taskkill: PID не переиспользуется между проверкой и остановкой. Неизвестный порт не трогается.
- Браузер открывается только после успешного healthz и проверки принадлежности новому процессу. На медленной Windows ownership-проверке отведено до 12 секунд внутри общего 45-секундного предела.
- Реальный 8000 переведён на этот способ запуска и повторно перезапущен им; сайт оставлен работающим. Исходные пользовательские untracked-файлы сохранены.

## Решения и пределы

Интерфейс и авторизация уже слиты автором в #160: эта ветка их не переписывает. Сервер production и реальный PostgreSQL не затронуты и не проверены. Полный интерактивный start.bat с повторным load_content над базой автора намеренно не запускался; его sync/serve проверены отдельно, миграция выполнена адресно. Неизвестный старый сервер при первом переходе со старого launcher нужно завершить вручную. Независимое ревью Claude остаётся задачей владельца PR.
