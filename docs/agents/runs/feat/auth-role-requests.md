# Регистрация, роли и вход

## Цель и договор

Гость видит отдельный вход/регистрацию без учебного меню. Регистрация ученика открывает курс; выбор «Учитель» создаёт заявку, которую подтверждает только владелец. Прямой доступ к данным чужих учеников остаётся закрыт серверными правами.

Baseline: `origin/main` = `17e6680adaa7b4c9ea0b4b8dfe2cda41e3d8bdc6` (PR #158 уже слит автором). Исходная папка занята веткой `agents/design-and-audit`; работа изолирована в `work/auth-role-requests`, ветка `feat/auth-role-requests`. Встроенное создание worktree не ответило дважды; использован `git worktree add`, исходная ветка и её файлы сохранены.

## Решения

- Автор подтвердил: выбор учителя создаёт заявку, права выдаёт владелец.
- Отдельный boolean заявки не участвует в `can_teach`. До одобрения заявитель имеет обычные ученические права, но после входа видит статус заявки. Одобрение сбрасывает заявку; отзыв роли возвращает в ученики.
- Роль выбирают при регистрации. При входе она определяется сервером по аккаунту, повторно выбирать её не нужно.
- Видимые обязательные поля: роль, почта, пароль и подтверждение. Имя не требуется. Отсутствующая роль у старого POST означает ученика; неизвестная роль отклоняется.
- Гостевая главная ведёт на вход. Пробная неделя 1, её уроки, объяснение маркеров и страница для учителей остаются публичны по действующей политике, в минимальной оболочке.
- Существующие защита CSRF, django-axes, проверка пароля, перенос гостевого прогресса и изоляция групп сохраняются. Почта/2FA/сброс пароля не добавляются.
- Визуальные проверки учебных страниц должны использовать настоящую сессию ученика. Фиксированный baseline ученика снимается с исходного SHA с прежним допуском 1 px; пороги не ослабляются.

## План и приёмка

1. Тесты новых требований → модель заявки/обратимая миграция → маршрутизация и одобрение в админке. Проверить подмену полей, неизвестную роль, next, подтверждение/отзыв, ограничения чужих групп.
2. Минимальная публичная оболочка, формы и статус. Проверить ошибки, клавиатуру, 375/390/768/1440, no-JS, reduced motion; ученический интерфейс сохранить.
3. Авторизованные визуальные fixtures и Visual review. Независимые `reviewer`/`ui_reviewer`, точечные тесты; полный набор один раз в конце. `check`, `makemigrations --check`, CSS/UI gates. Ветка заканчивается PR без слияния.

## Дизайн

Назначение: быстро создать аккаунт или вернуться в курс. Акцент: выбор роли с честным объяснением подтверждения. Шрифты: Literata/Golos, существующие paper/ink/green tokens. Композиция: компактная форма, книжная боковая заметка только на широком экране. Движение: только существующий фокус/нажатие; содержание и состояния видимы без JS.
