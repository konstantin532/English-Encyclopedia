# ADR 0001. Django + PostgreSQL на Supabase, серверные шаблоны

Статус: принято (2026-10-14)

## Контекст
Проект новый, с нуля. Нужны аккаунты учеников, большой структурированный корпус (6200 единиц, 60 историй, 60 стихов), прогресс и интервальное повторение, редактирование контента без программиста. Автор выбрал Django + Supabase.

## Решение
- Django 5.2: модели, админка для контента, аутентификация по почте (своя модель User с первого дня).
- База: `DATABASE_URL`. Локально SQLite, в продакшене PostgreSQL на Supabase через пулер (transaction mode, порт 6543). Для пулера отключены серверные курсоры и подготовленные запросы psycopg (`prepare_threshold=None`): соединения в пулере делятся между запросами.
- Supabase Auth не используется: Django ведёт пользователей сам. На всех таблицах `public` включается RLS без политик, чтобы автоматически открытый Data API Supabase ничего не отдавал.
- Интерфейс: шаблоны Django + чистые CSS/JS без сборщика. GSAP и шрифты (OFL) лежат в `static/`, внешних CDN нет.
- Реестры (маркеры, план курса) — код на Python с автоматической проверкой; в базу попадают через `post_migrate`.
- Контент — YAML в `content/`, загрузка идемпотентна (`load_content`), проверка — `audit_course`.

## Последствия
- Админка Django — редактор контента с первого дня.
- Для React или мобильного приложения позже есть приложение `api`.
- Миграции надёжнее гонять через прямое подключение (5432).
