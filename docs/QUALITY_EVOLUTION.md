# Quality Evolution: развитие тестов

В проект добавлена автоматизация на GitHub Actions: `.github/workflows/quality-evolution.yml`.
Она **не пишет код, не исправляет ошибки самостоятельно и не объединяет PR**.

## Что выполняется

- При каждом Pull Request и push в основные ветки: все тесты pytest с измерением покрытия строк и ветвей.
- Воспроизводимые случайные проверки разметки, HTML, IPA и вариантов ответов. По номеру запуска GitHub Actions количество проверок постепенно растёт от 76 до 1200, а максимальная длина входов — до 120 символов. Начальное значение зависит от номера запуска.
- Контроль минимального числа тестов и общего покрытия по файлу `tests/quality_baseline.json`.
- Три небольших мутационных проверки: временная копия кода намеренно ломается, существующие регрессионные тесты должны обнаружить дефект.
- Markdown-отчёты и артефакты покрытия/тестирования для последующего анализа. Артефакты сохраняются 14 дней.

По понедельникам в 03:17 UTC (06:17 по Москве) и при ручном запуске выполняется расширенный вариант фаззинга (до 6000 входных вариантов). **GitHub запускает cron только для workflow в ветке по умолчанию main**. Пока PR не принят в main, еженедельный запуск не активен.

## Как тесты становятся действительно лучше

1. Открыть отчёт `quality-report.md`, выбрать важный модуль с низким покрытием.
2. Добавить тест, воспроизводящий конкретный дефект (RED).
3. Исправить дефект и проверить GREEN.
4. При необходимости добавить новую контролируемую мутацию, которую новый тест обязан обнаруживать.
5. Поднять минимальные значения в `tests/quality_baseline.json` только после проверенных улучшений; не снижать пороги без объяснения.

**Важный этап калибровки:** изначальный порог покрытия равен 0%. После первого успешного запуска нужно повысить его до реально измеренного значения отдельным коммитом: до этого автоматизация **измеряет покрытие, но не запрещает его падение**. Порог числа тестов — 120, выбран для существующего main. Измерение числа тестов не гарантирует их качество, поэтому добавлены фаззинг и мутации.

## Запуск локально

```powershell
uv sync
uv run --with pytest-cov pytest -q --cov=apps --cov-branch --cov-report=json:coverage.json --junitxml=quality-junit.xml
uv run python scripts/qa_evolution.py fuzz --run-number 10 --seed 20261015
uv run python scripts/qa_evolution.py report --coverage-json coverage.json --junit-xml quality-junit.xml --baseline tests/quality_baseline.json --output quality-report.md
```

Расширение полноценным AI-агентом возможно отдельно: он может предлагать новые тесты в PR, а человек — проверять их смысл, надёжность и влияние на проект. Для этого потребуются отдельная настройка агента и разрешения. Контрольные мутации не равнозначны полному мутационному тестированию всего проекта.
