# Долгая и автономная работа

Цель — чтобы задача доходила до конца без автора и без потерь при сжатии контекста, новой сессии или смене агента.

## Перед стартом

1. Разбей задачу на **этапы**. Этап — проверяемый кусок, который заканчивается коммитом и зелёными тестами затронутой части.
2. Создай журнал запуска `docs/agents/runs/<ветка>.md`: цель и «готово, когда…», список этапов, допущения. Ветка — одна на задачу.
3. Если журнал уже есть, это продолжение: **сначала прочитай его** и начни с «Следующий шаг».

## После каждого этапа

- Коммит, затем запись в журнал: что сделано, какие команды и с каким итогом, следующий шаг одной строкой.
- Запись в журнал — до перехода к следующему этапу: после сжатия контекста или обрыва сессии продолжение начинается с неё.

## Когда автора нет

- Вопрос, без которого можно идти дальше, не останавливает работу: выбери самое разумное прочтение, запиши решение в журнал и в раздел «Решения без автора» описания PR, продолжай.
- Останавливайся только перед необратимым: удаление данных, необратимая миграция, слияние, облик всего сайта. Подготовь всё до этого шага и опиши выбор.
- Подзадача упёрлась (три безуспешные попытки, недоступная проверка) — пометь её BLOCKED в журнале с причиной и переходи к следующей независимой подзадаче, а не стой.
- Подтверждения в Codex идут через Auto-review (`approvals_reviewer = "auto_review"` в `.codex/config.toml`). Отказ проверяющего — сигнал искать более безопасный путь, а не обходить его другой командой. Хуки `guard.py` действуют всегда.

## Где запускать

- Работу ночью и на несколько часов запускай облачной задачей Codex: ей не нужен включённый ноутбук. Окружение готовит `scripts/codex_cloud_setup.sh`.
- Управление компьютером на Windows захватывает экран — для проверок интерфейса используй встроенный браузер и Visual review в CI.

## В конце

Журнал запуска остаётся в ветке как история задачи. Отчёт и описание PR — по AGENTS.md §8–§9.
