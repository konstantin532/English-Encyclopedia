# Поэтапная работа с дизайном

Этот навык — дирижёр: он вызывает другие навыки строго по очереди. Сам по себе ни один этап не начинай, пока не пройден предыдущий.

## Шаг 0. Понять размер задачи

- **Мелочь** — одна кнопка, отступ, цвет, подпись: только этап 1 (`polish`) и этап 4.
- **Страница или раздел** — все этапы по порядку.
- **Весь сайт** — по одной странице за раз; на каждую — все этапы. Начни с той, которую ученик видит чаще всего.
- **«Запили сайт» про новую функцию, а не про вид** — это не дизайн: обычная работа по AGENTS.md, интерфейс по `encyclopedia-design`.
- **Непонятно, вид или функция** — один вопрос автору: «Улучшить, как выглядит, или добавить новую возможность?»

## Этапы

0. **Направление.** [DESIGN.md](../../../DESIGN.md) и навык `encyclopedia-design` — главный закон. Ничто ниже его не отменяет; при споре побеждает DESIGN.md.
1. **Диагноз и чистка — Impeccable.** `$impeccable critique` и `$impeccable audit` → список проблем по приоритету; затем по находкам `arrange`, `typeset`, `polish`. Если нет `PRODUCT.md` — `$impeccable init`, ответы бери из DESIGN.md и AGENTS.md. Команду `document` не запускай: она перезапишет DESIGN.md.
2. **Вкус — Taste Skill.** `$design-taste-frontend` в режиме доработки существующей страницы. Направление уже выбрано в DESIGN.md — новое из его 20 не выбирай. Фото из внешних коллекций не бери: картинки только по навыку `ee-illustration`. Используй его проверку в браузере на трёх ширинах и проверки против шаблонного дизайна; до 3 кругов.
3. **Движение — GSAP.** `$impeccable animate` решает, что и зачем двигается; код — навыки `gsap-core`, `gsap-timeline`, `gsap-scrolltrigger`, `gsap-plugins` (Flip — перестройка карточек и списков, SplitText — текст). Переходы между страницами — View Transitions браузера (`@view-transition { navigation: auto; }`). Мелкие состояния — CSS. 180–450 мс, `prefers-reduced-motion`, без scroll-jacking, без JavaScript всё видно. `$motion-react` не используй: React в проекте нет.
4. **Приёмка.** Навык `ui-acceptance` и агент `ui_reviewer`, затем комментарий Visual review в PR.

## Между этапами

- После каждого этапа — запись в журнал запуска `docs/agents/runs/<ветка>.md` (навык `long-run`): что нашёл, что изменил, снимки до/после.
- Навыка этапа нет в окружении (Taste Skill и Impeccable стоят только на компьютере автора, в облаке их нет) — этап BLOCKED с причиной и переход к следующему. Не заменяй его догадками.
- В описании PR перечисли этапы со статусом: пройден, BLOCKED или пропущен по размеру задачи.
